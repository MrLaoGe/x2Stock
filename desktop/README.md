# x2Stock desktop runtime and updates

Build with Node 24: `npm ci` in frontend and desktop, frontend typecheck/style/build, then `npm run pack:dir` in desktop. Clean committed source is mandatory. This builds a directory in desktop/release/win-unpacked; final integration owns copying the complete runtime into `desktop-runtime/win-x64` and the root `启动.bat`. No new standalone Windows ZIP is produced. Build version comes from root VERSION through electron-builder extraMetadata. The resource build manifest contains schema/repository/version/build_source_sha/source_tree_hash/platform/arch; the parent source SHA is not the later commit adding binary resources. For a previously verified local Electron distribution ZIP, optional `X2STOCK_ELECTRON_DIST` avoids another network download. The builder removes only its stock default_app.asar/version templates from ignored output and validates the exact 73-file list in updater/runtime-files.json, also consumed by the project Python verifier.

Run `npm test` in desktop for synthetic policy/archive/rollback/IPC/profile checks. Frontend update UI consumes [update-contract.d.ts](update-contract.d.ts); renderer never supplies URLs, file paths, tokens or command lines. Background checks start asynchronously after local page load and repeat at six hours (network failure backs off to twelve/twenty-four hours); manual checking remains available. Installation requires an exact checked release ID/version and confirmed=true. The helper is separate from the current runtime and initialized before normal profile/instance handling. Sandbox/contextIsolation remain enabled, nodeIntegration disabled. Status is finite and monotonic per process; applying means pending closure, never success.

## Feed and publisher contract

Repository is public HTTPS MrLaoGe/x2Stock only. At most three pages of 100 releases are inspected. Eligible releases have a valid integer SemVer tag, major zero, prerelease=true, draft=false, an actual publish time no later than checking, and a version strictly newer than the bundled version. Metadata asset is `x2Stock-<version>-update.json`, uploaded, <=16 KiB, unique, with a GitHub API sha256 digest. Checks verify that digest before parsing. Release tag refs (including bounded annotated tag resolution) must identify metadata source_sha exactly.

Metadata schema: `{schema:1,repository:'MrLaoGe/x2Stock',version,source_sha,source_tree_hash,archive_url,archive_sha256,archive_size,runtime_subdir:'desktop-runtime/win-x64'}`. Archive URL must be exactly `https://codeload.github.com/MrLaoGe/x2Stock/zip/<source_sha>`. Size is bounded at 512 MiB compressed / 1200 MiB declared expanded / 5000 entries. All entries are checked for traversal, device names, ADS, case collisions, encryption and link types; extracted files additionally get CRC/size validation. Source files are streamed to a canonical tree hash; only the runtime subtree is written. x64 PE, required Electron resources and matching version/tree build manifest are required. A GitHub regenerated archive with changed bytes fails closed.

Canonical source tree input is Git tracked frontend/**, desktop/** and VERSION, excluding path components node_modules/dist/release/renderer/build/__pycache__ and .pyc/.tsbuildinfo. File content means Git index blob bytes, obtained from `git ls-files --stage -z` and `git cat-file blob <oid>`, so LF/CRLF checkout conversion does not change identity. Source differences from HEAD, unmerged entries, nonregular source files and untracked nonignored source refuse a build. SHA256 of each file is listed in byte-sorted path order as `<lowercase sha256>  <relative path>\n`, then SHA256 of the full UTF-8 list. This excludes desktop-runtime binaries, avoiding final-commit recursion while binding runtime to exact code/version. Root/CI must build from clean tracked source, commit the complete public runtime, tag the final exact commit, enable LFS include-in-archives, and independently verify the official source archive is runnable. Official archive prefix must equal x2Stock-<exact source_sha>; case/NFC aliases and runtime files outside the allowlist are refused.

After official archive availability, `node desktop/scripts/release-metadata.mjs` checks the local runtime and two actual GitHub archive downloads, verifies source/runtime content, and writes metadata only beneath ignored .local. It does not publish. CI must use Node 24 (ZIP CRC support), preserve verified bytes, and upload metadata to that exact prerelease; GitHub asset digest must be present before runtime updater will accept it. Unpublished/no-assets releases yield truthful no-update/no-assets status. An invalid feed or offline check leaves local app usable.

Trust is HTTPS to GitHub, repository account/tag/asset control and GitHub digest + archive checksum, not an independent publisher digital signature. Account compromise is outside this trust model. Independent code signing is not implemented; current runtime is unsigned. Release publication and real public cross-version update remain external acceptance until matching trusted assets exist.

## Data, apply and recovery

Existing `%APPDATA%/XXStock` profile/session/cache/downloads are reused when an old profile or session exists. New installs use `%APPDATA%/x2Stock` for those directories. Legacy data is never copied/deleted. Updates always stage separately under `%APPDATA%/x2Stock/updates/jobs/<uuid>`; source project .git/.env/.local and application user data are untouched.

Apply requires the executable to run from an actual `desktop-runtime/win-x64` directory outside AppData. A checked runtime is copied to a unique sibling .x2stock-next directory. An immutable SHA256-bound job contains target/next/backup and all old/new file hashes. An external copy of the current Electron runtime waits for the old PID to exit, verifies every file/hash/layout again, and performs two same-volume directory renames: current→backup, next→current. Each rename is atomic; the pair has a short gap and is not a filesystem-wide atomic transaction. Durable journal states retain evidence and interrupted-transaction recovery uses only validated known paths. Backup is preserved. Launch/health/second-rename failure attempts rollback and reopens verified old code. If OS locks prevent rollback, preserve both directories/journal and show rollback error; no data deletion or blind overwrite.

Health acknowledgement is bounded to 30 seconds and requires expected runtime manifest/tree/version, the correct local renderer URL and nonempty #root text. A title or did-finish-load alone is insufficient. The helper has its own profile to avoid lock collision; normal app is single instance. Install lock and main busy state prevent duplicate update commands. Staging, backup and helper files are retained for inspection rather than automatically deleting deliverables/user data.

Before either rename, a verified full copy of the old runtime is prepared at fixed desktop-runtime/.recovery with a <=1 KiB regular pending.json containing exactly schema/id/job digest. The root UTF-8 CRLF BAT uses this fixed local EXE with --x2stock-recover only if win-x64/x2Stock.exe is absent. Normal startup with a pending marker verifies the same bootstrap and dispatches it outside the target before profile/instance setup; candidate health startup alone bypasses recovery. The bootstrap derives sibling win-x64, verifies the immutable appData job, containment, previous hashes and active-helper lock. It restores only known transaction paths. A rollback-failed journal retries restoration; lack of a verifiable old runtime exits with a finite failure. Marker removal happens only after verified restoration or healthy journal commit, so another interruption retains the entry point. Repeated stock recovery copies are preserved at unique sibling names. Runtime rename retries for transient Chromium/AV locks are bounded at ten seconds.

Windows fixture command: `node desktop/scripts/helper-smoke.cjs <fresh OS-temp/x2stock-fixture-name> healthy|blank|interrupt-backup|interrupt-target`. Only a nonce-bound native-realpath marker in OS temp enables an isolated appData/profile/instance realm and test hooks. Offline mode applies Chromium DNS blocking and rejects Node updater fetch, without affecting production. Helpers/candidates inherit the realm; only owned temp runtime processes are closed, with cleanup in finally. The test verifies exact local CDP URL, nonempty root, English localStorage persistence, native visible/responding window, old/new file hashes and synthetic project .env retention, five seconds after helper exit. blank deliberately empties the candidate renderer in the validated test realm to test bounded health rollback. The interruption modes kill the owned helper after first/second rename and launch the CRLF root BAT, exercising actual bootstrap recovery. These are same-version synthetic runtime transactions, not a real public cross-version download or physical power-cut test.

Verified synthetic tests are not a substitute for the final packaged real update test. Initial no-legacy profile, physical text zoom/Windows scaling, successful public-version update, and real locked-file/permission/power-loss recovery require independent packaged acceptance. Current visible previews and historical artifacts remain preserved.
