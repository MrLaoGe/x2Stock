# 下一轮入口：数据中心与选择性迁移

状态：阶段 0 模块设计入口，**未实现**数据库、网页、采集或迁移功能。模块在[功能清单](catalog.md)与[路线](../roadmap.md)中推进；架构与字段分别遵循[架构设计](../architecture.md)、[接口契约](../contracts.md)。

## 目标与首批范围

建立新版独立的数据底座，让用户知道哪些数据来自何处、是否完整、是否过期，以及历史是否满足量化时间约束。首批只承接证券主表、交易日历、日行情、日基本面和复权因子，并对旧Tushare行情完成可审计的选择性迁移。

先通过详细设计评审，再实现最小闭环。新闻、资金流、板块成员、盘中行情、研究报告和社区情绪按后续模块展开；产品内Agent、量化策略、回测和交易不进入这个闭环。AI不可用或未配置不妨碍数据中心工作。

## 页面与接口意图

数据中心呈现数据集、来源、最新业务日期、最后成功采集时间、覆盖和缺口。证券详情展示日行情与字段来源；迁移页面先呈现接受/拒绝/未知的预检结果，再展示独立批次的进度和发布/回滚结果。不要在数据页面展示内部模型辩论或把来源符合误写成数据真实已验证。

所有业务API使用 `/api/v1`。本模块规划提供数据集状态查询、证券与日行情查询、采集任务、迁移预检/发布/回滚与批次状态查询；**端点路径、schema和作业操作权限在下一轮详细设计锁定**，本文不声称可调用。user/workspace由服务端本地身份上下文确定，默认 `local/local`，普通请求不能任意指定其他归属。

前端不直连provider，不接收密钥或完整旧路径。provider失败返回明确作业问题，不将空响应写成成功数据；过期数据可查看但保留业务日期和过期标记。配置默认关闭AI，见[配置说明](../configuration.md)。

## 多 Agent 开发分工

- 数据Agent定义来源、单位、时间证据和迁移判定；后端Agent实现独立存储、作业和事务；前端Agent按冻结契约实现常规数据页面。
- 独立审查Agent检查来源混入、归属过滤、时间泄露、幂等、断点和回滚竞态，并用测试场景验证，不只复述实现者结论。
- 各Agent使用独立分支/worktree和明确文件归属；主Agent集成后验证。仅允许读旧项目，不启动旧调度、不复制真实资产到公开仓库。

详细方案记录到模块文档与台账；完成后分别标记已实现、仅设计、待核验。开发Agent分工不等于产品内研究Agent已实现。

## 实施验收门槛

1. 不配置AI即可启动独立部署；首次启动不隐式修改表结构，不读旧配置或旧路径。
2. 本地user/workspace下查询和任务正确归属；合成双归属数据验证跨归属查询、发布和回滚均被拒绝。
3. 允许来源才能入库；排除来源、未知血缘、混合派生及未授权新浪样例全部拒绝，拒绝统计可核对。
4. 单位、证券编码、业务日期及时间语义测试通过；2019历史仅有价格且缺基本面/复权/首次可用时间时明确显示缺口。
5. 采集限流、权限不足、空响应、分页不完整与上游失败不会覆盖有效数据；历史补缺范围有明确上限与进度。
6. 同快照重复导入、分块中断恢复、并发发布、回滚重试和前序批次撤销符合[迁移验收](../data/migration.md#验收场景)。尤其验证导入后正常采集同键更新不会被回滚破坏。
7. staging不可被正式查询读取；来源、输入revision、批次及质量可追溯；日志和前端响应无密钥、私人正文或完整本地输入路径。
8. 原始与派生数据分层；`tushare_derived` 不冒充官方成员，未知历史可用时间不作point-in-time证明，不未来填权。
9. 以合成数据自动化验收，真实历史只在本地验证数量和抽样质量；报告本次实际导入量，不沿用2026-10-08审计数量作通过依据。
10. 记录数据库备份与恢复验证、业务测试、前端构建、仓库校验及剩余来源权限缺口；满足后才推进下一业务模块。

本轮仅交付设计和上述验收入口；后续实施任务需先冻结详细接口、字段与状态机，再根据测试证据更新完成状态。
