# 功能审查与模块清单

状态：阶段 0 功能盘点与归并，不代表表中模块已经实现。清单综合旧网页、后端 80 余个接口、业务脚本和 Skill 能力；旧导航没有入口的能力也纳入审查。首个实施模块为 [数据中心与迁移](data-center.md)，后续顺序见 [阶段路线](../roadmap.md)。

“基础必需”表示新版底座设计约束；“常规研究”表示进入后续模块设计范围；“特色候选/待审查”表示保留资料与算法参考，需另行确定口径和价值；“远期”不进入首期实现。候选不等于取消，也不默认迁移旧功能全部参数或交互。

## 模块设计与迁移顺序

1. **数据中心与迁移**：核验来源能力、统一契约、独立存储、身份边界、旧资产预检与迁移验收。先迁移可追踪且允许的事实，不为省采集成本放行不明血缘。
2. **常规研究模块**：逐轮确定页面、查询、采集计划和验收；页面上线前先确保输入数据可用。旧算法通过合成测试与口径审查后再选择性移植。
3. **特色指标**：每项单独登记假设、公式、版本、验证方法与限制；保留、调整或停用由对应模块讨论决定，不从旧页面名推断产品结论。
4. **研究 Agent 与量化**：在可信输入、报告证据和历史时间边界建立后设计；角色体系见 [Agent 设计](../agents.md)，不提前启用交易执行。

导航归并后仍为各能力保留接口与设计索引，但不兼容旧 API 路径、不导入旧 Git 历史、不把旧项目作为依赖。数据兼容通过显式导入与契约转换完成，而非两项目共用数据库或运行目录。

## 每轮必须交付的模块记录

模块文档应说明用户目标、旧能力对应关系、已选取舍、输入与来源、数据层及归属、时间与缺失语义、界面入口、任务、迁移兼容、行为验收和未解决限制。沿用 [协作规范](../development/collaboration.md) 和 [交接模板](../development/handoff-template.md)，状态只在实现与验证完成后改为已实现。
