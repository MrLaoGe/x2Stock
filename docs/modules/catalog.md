# 旧功能参考与新版模块选择目录

状态：阶段 0 功能盘点与归并，不代表表中模块已经实现。清单综合旧网页、后端 80 余个接口、业务脚本和 Skill 能力；旧导航没有入口的能力也纳入审查。下一项本体任务为[最小应用骨架](application-skeleton.md)，当前仅规划未实现；首个业务模块仍由用户选择，见[阶段路线](../roadmap.md)与 [ADR 0006](../adr/0006-module-first-new-project.md)。旧表、旧模块或大数据量不自动构成新版需求或授权。

“按需基础”表示已选模块启用相应能力时须遵守的设计约束，不要求骨架先实现；“常规研究”表示可供用户选择的研究方向；“特色候选/待审查”表示保留资料与算法参考，需另行确定口径和价值；“远期”不进入首期实现。候选不等于取消，也不默认迁移旧功能全部参数或交互。

## 模块选择与数据取得

1. **最小应用骨架**：只规划独立前后端、PG、显式结构升级、配置健康、空工作台与部署；无需旧项目/凭据/AI，不预建未选业务表，不部署采集或导入任务。
2. **用户选业务模块**：市场、个股、板块、新闻、个人研究、报告等均可逐轮选择，不设固定顺序，只补最小依赖。先确定新版功能，再逐数据集锁定字段、证券/日期范围、粒度、单位、时效、留存及功能验收，选择新采集、有限旧导入、新版重算或不支持。数据中心只管理已启用模块的配置、任务、来源/质量。
3. **特色指标**：每项单独登记假设、公式、版本、验证方法与限制；保留、调整或停用由对应模块讨论决定，不从旧页面名推断产品结论。
4. **研究 Agent 与量化**：在可信输入、报告证据和历史时间边界建立后设计；角色体系见 [Agent 设计](../agents.md)，不提前启用交易执行。

目录与导航都是参考，不要求空工作台展示全部业务入口或预建接口。默认不迁移旧数据；共有功能只构成评估条件，选定模块、数据集、字段、范围和批次后另行授权导入。新采集满足需求即可独立上线，不等待可选迁移；历史缺失如实限制相关功能。旧算法逐项审查与重算，不兼容旧 API 路径，不导入旧 Git 历史，不共用数据库或运行目录。

项目 Skill 规则见 [组织规范](../development/skills.md)，发布验收见 [发布规范](../development/releases.md)。旧 Skill 的业务规则逐项审查，不整包搬入新目录；登记为 business 也不会获得采集或交易权限。

## 每轮必须交付的模块记录

模块文档应说明用户目标、已选新版功能及最小依赖、旧能力参考、逐数据集字段/范围/粒度/单位/时效/留存、取得方式与来源、归属、时间与缺失语义、界面、任务、可选迁移授权、行为验收和限制。功能状态、数据取得状态、迁移状态分别记录，评估不等于执行授权。沿用 [协作规范](../development/collaboration.md) 和 [交接模板](../development/handoff-template.md)，状态只在实现与验证完成后改为已实现。
