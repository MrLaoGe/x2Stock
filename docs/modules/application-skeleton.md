# 下一项本体任务：最小应用骨架

状态：金融后台、事务存储与配置健康仍是**规划**；Windows空工作台/三语由UI-001先行实现，项目随附runtime与更新另验。本入口不扩大业务范围。依据 [ADR 0006](../adr/0006-module-first-new-project.md)、[架构](../architecture.md) 和[路线](../roadmap.md)。

## 范围与最小闭环

桌面当前采用React/TypeScript/Vite和Electron，完整runtime随项目，根BAT相对启动；浏览器仅调试。未来按已选模块启用随包Python/FastAPI、SQLite WAL及配置健康，PG/Compose仅未来服务器方案，不是用户启动前提。选择及证据见[ADR0008](../adr/0008-windows-desktop.md)。使用显式 Alembic 命令管理新版数据库结构；应用导入、普通启动和查询不得隐式建表。骨架仅包含自身必要的结构与部署配置，不预建未选择业务模块的行情、新闻、板块等业务表。

用户没有旧项目、Tushare 凭据或 AI 配置时也能启动并看到空工作台、服务健康和安全的缺配置提示。健康检查只检查自身服务和配置，不暗中探测 provider、采集数据或调用 AI。具体健康接口、结构版本、目录和部署步骤在实施时评审确定，本文不锁定未经讨论的业务接口。

数据库结构升级与旧数据导入必须分别说明。前者使新应用结构达到目标版本；后者是用户选模块后、选定数据集/字段/范围的独立操作。骨架不附带全量数据中心、来源适配器、采集 worker/调度、通用搬库工具、产品 Agent 运行器、常驻业务服务或交易接口。未来 worker 仍遵循既有独立架构，在已选模块需要后台任务时才实现。

## 后续实施验收

1. 干净Windows项目下载能由根BAT打开本地桌面，后续按模块启动随包Python/SQLite；默认仅本机访问，不依赖旧路径、开发工具内置运行时、数据源凭据或 AI。
2. 显式执行结构升级可验证目标版本；应用导入与普通启动不变更结构，不创建未选模块业务表。结构升级失败给出安全诊断，不转为旧库修复。
3. 空工作台、配置状态和自身健康可查看；无凭据是可解释状态。启动和页面读取不产生 provider/AI 请求或业务采集、导入任务。
4. SQLite、私有数据目录、配置与密钥均独立；前端、日志、错误和公开资产不含秘密。默认网络边界与本地身份约束符合架构，未来多用户能力不冒充已实现。
5. 后端检查、前端构建和适当部署/结构升级验证通过；按实际交付更新台账和交接。迁移模块的批次、断点、回滚验收不作为骨架门槛。

骨架完成后，首个业务模块仍由用户选择。按[模块目录](catalog.md)确定新版功能和最小依赖，逐数据集填写设计；不按旧表大小或目录顺序自动选题。
