# 旧数据资产审计快照

状态：阶段 0 已完成只读抽查与本地结构统计；未迁移数据。以下数量均为 **2026-10-08 本地审计快照**，旧服务可能继续写入，不能作为未来导入固定数量或完整性承诺。旧来源标签是代码记录的血缘线索，**不等于数据真实性证明**。

本页保留历史审计事实，不构成新版需求或导入授权。默认不迁移，8,991,131 行旧行情不是必须迁移目标；用户选模块、定义所需数据后才评估价值并按需另批导入，见 [ADR 0006](../adr/0006-module-first-new-project.md)。

旧项目为 ReviewStock_Codex；以下位置均相对于旧仓库根目录，只用于说明审计依据，不作为新版运行路径。[迁移设计](migration.md)规定导入判定，[来源能力矩阵](sources.md)规定允许来源。

## 排除数据与预期缺口

| 数据 | 必须排除的部分 | 对新版的影响 |
| --- | --- | --- |
| 概念成员历史 | zhitu 1,182,305 行 | 不能延续旧概念成分历史，需要认可来源的新边界 |
| 概念成员区间 | zhitu 141,209 行 | 旧题材历史成员区间不可复用 |
| 盘中行情 `intraday_quotes` | 70,291 行，新浪价格与东方财富底座混合 | 新浪未获授权，不能导入；重新建设盘中覆盖 |
| `stock_master` | 5,407 行顶层标签为新浪与东方财富混合，508 行为Tushare | 更新会保留旧字段却覆盖总来源，不能证明全字段来源；优先重建轻量证券主表 |
| 旧派生结果 | 拥挤度 215,703、题材强弱 3,974、风险机会日结果 18 行等 | 缺少完整输入血缘；不作为新版结果导入，后续重新计算 |
| 日复盘文件与报告 | 含排除来源或来源不明的文件、混合报告 | 仅记录缺口，不根据文案或文件名猜测来源 |

日复盘 `manifest.json` 通常只记录全日请求统计和优先级。即使某日清单含允许来源，也不能证明每个文件或字段均来自允许来源。仅有 `public`、`local cache`、旧路由名或汇总来源时，应拒绝导入，除非补足可验证的原始文件关系。

## 代码依据与风险

| 旧相对代码位置 | 观察 |
| --- | --- |
| `apps/backend/xiaoxie3/data_sources/router.py` | 个股、指数和5分钟行情优先使用 zhitu；新闻及缓存存在混合与回退 |
| `apps/backend/xiaoxie3/market_crowding.py` | 日行情有 OHLCV、基本面、复权字段来源；成员记录有行来源；评分不具备完整血缘 |
| `apps/backend/xiaoxie3/backfill_capital_flow.py` | 记录Tushare回补、当前SW成员回溯与偏差 |
| `data/skills/current/_shared/scripts/api_client.py` | mairui仍存在于共享token池；移除不只涉及后端provider |
| `apps/backend/xiaoxie3/config.py` 与 `paths.py` | 配置、路径和目录创建绑定旧根目录；不能作为新版依赖导入 |
| `apps/backend/xiaoxie3/database.py` 与两类 Store 初始化 | 初始化可建表、迁移和清理，审计与迁移禁止调用这些入口 |

旧系统只有部分监控表具备 `owner_key`，交易动作和新闻等没有完整用户归属；新版不能继承为多用户隔离。旧配置有本地密钥但本审计不披露内容。新仓库不继承旧Git历史、个人股票池、研究档案、密钥文件或真实响应。

## 后续审计边界

下一项本体任务为[最小应用骨架](../modules/application-skeleton.md)，不启动旧数据映射或搬库。骨架后由用户选模块，先定义新版功能与数据集，再评估本快照的价值；选定字段、证券/日期范围和批次并另行批准时才设计导入。新闻、资金流、社区与历史题材也只在相应模块被选定后继续审计，不因旧数量多就自动成为任务。

历史首次可用时间和修订历史尚未全面证明。数量多、跨度长不等于可以进行 point-in-time 回测；量化数据缺口必须随数据公开到用户界面，禁止用当前成员或未来复权因子补成“无偏历史”。
