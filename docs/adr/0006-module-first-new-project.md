# ADR 0006：独立新建、用户选模块与按需旧数据复用

日期：2026-10-08；状态：accepted。supersedes [ADR 0001](0001-project-boundary.md) 中“下轮先数据中心与迁移”的顺序，以及 [ADR 0003](0003-provenance-and-migration.md) 中可被理解为默认保留大量历史数据的安排；其来源准入、隔离和安全规则继续有效。0005 留给并行的多对话 Skill 决策，本决策不占用它。

## 背景

旧 3.0 功能和 8,991,131 行日行情是审计事实与需求参考，不构成新版任务。把全数据中心、旧行情导入和固定业务队列列为前置，会让新项目被旧资产牵引，也混淆结构升级与数据导入授权。

## 决策

x2Stock 按独立新项目建设：**用户选模块 → 明确新版功能 → 定义所需数据 → 评估旧数据价值 → 按需另批导入**。默认不迁移旧数据。共有功能仅是评估条件，用户须另行选定模块、数据集、字段与证券/日期范围并批准导入批次；评估不等于执行授权。

下一项本体任务为[最小应用骨架](../modules/application-skeleton.md)：前后端、独立 PostgreSQL、显式 Alembic 结构升级、配置健康、空工作台和部署。无需旧项目、数据源凭据或 AI 即可启动。本轮只改文档，不实现骨架。Alembic 管理新版数据库结构，旧数据导入是另行启用和验收的业务操作。

骨架后由用户选择市场、个股、板块、新闻、个人研究、报告等模块，不设市场→行情→新闻的固定顺序。依赖只补当前功能的最小前置；未选模块不创建业务表、不部署采集/导入任务。数据中心只管理已启用模块的配置、任务、来源与质量，随需求增长，不先做所有来源或通用搬库平台。

每个模块逐数据集确定字段、范围、粒度、单位、时效、留存及功能验收，选择新采集、有限旧导入、新版重算或不支持。功能状态、数据取得状态、迁移状态分开记录；新采集满足需求即可上线，不等待可选迁移。历史缺失及未知 `available_at` 如实限制相关功能，不伪造事实或无偏回测能力。

只接受 Tushare、东方财富、财联社；排除 zhitu、mairuiapi、未知来源与不可拆混合。旧指标在新版重算，不自动复制旧配置、调度、待执行任务或 AI 报告。旧库只读、新旧物理隔离、新运行不依赖旧路径。选定导入后仍须稳定快照、血缘/质量/时间检查、批次、幂等、断点与安全回滚：有效新数据优先，撤销旧导入不能损坏后续采集。这些验收随导入模块启用，不强加骨架。

角色职责与金融长期方向保持：角色覆盖不是任务授权，历史迁移角色仅在评估或选定导入时启用。现有 Skill、角色模板、协调工具、行为测试和发布流水线由并行任务独立验收，本任务不修改其实质；仅在其验收发布后集成说明。阶段 3 研究、阶段 4 量化、阶段 5 单独授权执行，以及技术栈和 MIT 均不变。

## 影响与验收

当前入口统一指向骨架与用户选模块；旧功能目录、旧 ADR、审计数量和历史发布材料保留。模块可在无旧库的环境独立交付；需要历史时再说明收益、成本、缺口与批次授权。实现者不得因角色或旧表存在扩大范围。路线、数据中心、迁移规范和台账同步，由独立角色检查矛盾及需求覆盖。
