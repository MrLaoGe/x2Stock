# 模块交接模板

复制为 `docs/development/handoffs/<任务ID>-<模块>.md`，用实际结果填写，不保留含糊的“已完成全部”。

## 任务

- ID / 模块 / 日期 / 分支：
- 用户目标和本轮交付边界：
- 前置决策 / ADR：

## 最终状态

| 能力 | 状态（已实现 / 设计确定 / 未验证 / 延后） | 产物和证据 |
| --- | --- | --- |
| 填写能力 | 填写状态 | 文件、提交或验证结果 |

分别填写功能状态、数据取得状态和迁移状态，不以一项 completed 替代三者。新采集满足需求即可验收功能，迁移可为未选/评估中/待授权/已授权待实现/已验收/失败；历史缺失及未知可得时间的限制持续保留。

## 输入输出与兼容

- 用户选定模块、新版功能与最小依赖：
- 逐数据集字段、证券/日期范围、粒度、单位、时效、留存、功能验收：
- 取得选择（新采集 / 有限旧导入 / 新版重算 / 不支持）及证据：
- 输入数据、来源、权限、日期、单位、复权和缺口：
- API / 数据结果 / 页面 / 任务输出：
- 用户归属与 secrets 边界：
- 可选旧导入的评估结论与另批授权（模块/数据集/字段/范围/批次）；未选不执行：
- 旧资产复用和来源排除；新旧隔离：
- 版本与迁移影响：

## 验证

- 执行命令和结果；失败场景：
- 迁移数量、校验摘要、幂等/断点/回滚（如适用）：
- 独立评审发现及修复：
- 发布状态（本地 / 已提交 / 已推送）与可验证链接：

## 下一轮

- 已知问题及影响：
- 未核验假设与下一项证据：
- 下一任务 ID / 文档 / 推荐操作：
- 必须保护的本地修改或数据：
