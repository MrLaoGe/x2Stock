# Agent 角色与证据设计

状态：阶段 0 的角色与协作契约已确定；产品内 Agent 仍为后续阶段设计，不存在运行器、长期调度或交易权限。

完整模板位于 [multi-dialogue-development 角色模板](../.agents/skills/multi-dialogue-development/references/roles.md)，机器覆盖契约位于 [agent-coverage.json](development/agent-coverage.json)。业务与工程池共 40 个角色：数据 4、市场研究 8、报告 6、个人研究 3、量化 7、执行 3、工程 9；另有老板和 PM 两个协调角色，总计 42 个。

## 关键边界

数据采集、标准化、迁移和时间核验分开；板块、个股技术、财务、资金、新闻和方法验证各自负责；盘前按截止快照冻结，盘中追加，盘后不能回填盘前；策略研究、程序、引擎、实验、独立评估、模拟偏差和风险分开；阶段 5 订单执行另行授权。

PM 每项任务必须绑定“业务专责 → 实现责任 → 独立验收”；独立验收从需求和候选入口 forward-test，不能只复述实现说明。缺失保持缺失，冲突保留证据，阻断依赖不执行。业务 Skill 只描述职责，不授予工具、密钥、采集写入或交易权限。

每次研究运行关联用户/空间、`snapshot_id`、`as_of/cutoff`、角色、提示词/方法/策略版本、工具结果、预算、审核结论和终稿版本。确定性检查负责来源 ID、时间截止、单位/复权、数字重算、引用和归属；失败发布 failed/partial/insufficient。真实交易记录、方法资产、凭据和 provider 响应不进入公开仓库。

阶段 0 只建立文档、Skill、角色和协作规则；阶段 1 数据底座；阶段 2 常规研究；阶段 3 证据型报告；阶段 4 量化验证；阶段 5 才在单独授权下设计券商、风控、订单状态和恢复。角色目录不是已实现能力清单。
