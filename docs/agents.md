# Agent 角色与证据设计

状态：开发协作已采用；产品内 Agent 仅为阶段 3 设计，不存在运行器或长期调度。

## 两套角色

开发 Agent 面对代码、设计和验收，产品 Agent 面对市场证据与研究结论。开发权限不意味着产品 Agent 获得用户凭据、任意网络、数据库写入或交易执行权限。产品初期角色共用用户配置的 GPT 模型，不建设多厂商智能路由。

## 开发角色

| 角色 | 负责的具体输出 | 交叉约束 |
| --- | --- | --- |
| 主 Agent | 模块目标、契约、文件分工、集成与台账 | 不以子 Agent 的“已完成”替代检查 |
| 数据 Agent | 来源矩阵、单位、覆盖、迁移过滤及缺口 | 不能凭标签推定未知来源，也不改旧库 |
| 后端 Agent | API、归属过滤、业务规则、迁移与任务 | 以数据契约和行为测试验证，不调用旧初始化 |
| 前端 Agent | 信息架构、页面、状态与组件 | 不能隐去缺失/过期状态或自行请求 provider |
| 审查 Agent | 独立检查证据、边界、失败场景和验收 | 报告可复现问题，不只复述实现说明 |

本轮文档使用主 Agent、数据 Agent、架构 Agent 与独立审查；角色可以合并，但写入文件必须有单一所有者。

## 产品研究工作流

| 角色 | 输入 | 输出与发布条件 |
| --- | --- | --- |
| 数据核验 | 冻结快照、来源记录、覆盖和时间 | 可用证据列表、冲突/缺口、可分析范围；不能生成缺失事实 |
| 研究分析 | 可用证据、用户研究问题、确定性指标 | 假设、支持证据 ID、反证条件、适用时间和不确定性 |
| 反方审查 | 同一冻结证据、分析稿 | 检查替代解释、时间穿越、样本偏差、推断过度及未覆盖风险 |
| 终稿复核 | 分析稿、反方意见、机器检查结果 | 保留分歧的终稿，或返回未通过项；不删除反证伪造一致性 |

角色间交换结构化研究材料和证据引用，保存可审计的结论、工具调用和评审意见，不要求记录或披露模型私有推理过程。输出格式在阶段 3 详细设计时固定。

独立确定性检查负责证据 ID 是否存在、记录时间是否在截止内、单位/复权是否一致、数字能否由事实重算和引用是否准确。模型意见不能覆盖这些检查。

## 一个可验证的场景

用户请求某交易日的盘前报告。系统先冻结该时点可获得的行情、新闻与用户关注列表，并生成 `snapshot_id` 和内容摘要；分析 Agent 只能引用该快照。反方 Agent 检查某个“资金持续流入”的表述是否确有连续交易日数据支持。若只有一日快照，终稿必须收紧表述或标注证据不足，不能靠多个角色同意而保留原结论。

保留旧盘前 `PRE_OPEN_0850` 的时间约束作为迁移参考：隔夜消息截止 08:30、08:45 完成采集、08:50 冻结生成。历史补跑必须使用当时证据；不存在快照时标记无法正式回放，不以当前历史库重构“当时已知”。最终各报告时段在报告模块设计中明确。

## 运行记录和失败

每次产品 Agent 运行关联用户/空间、研究问题、快照、角色和提示词版本、模型与协议、工具调用结果、token/估算费用、审核结论和终稿版本。快照与终稿只追加版本，不被重跑覆盖。

外部文本仅作为资料，不能改变 Agent 权限或触发写入。工具仅暴露白名单研究读取；秘密不进入提示词。超时、预算耗尽、结构化输出失败或证据检查失败时发布明确的失败/部分完成状态，不冒充完整报告。审查失败至多进行一次明确的修订尝试，仍失败则停止并保存意见，不进行无限付费循环。

## 量化与执行边界

阶段 4 的策略版本、行情口径、手续费、滑点、停牌/涨跌停约束和 point-in-time 数据一起冻结。分别验证历史回测、样本外与模拟交易，记录候选失败情况，避免只报告最优参数。

阶段 5 才设计券商适配和订单状态机。研究结论转换为明确策略意图后，必须通过确定性仓位/资金/价格/时效和幂等检查；研究 Agent 没有直接下单权限。交易启用、停止和异常恢复需要独立验收。当前不创建交易接口、自动买卖任务或长期运行承诺。
