# x2Stock 总体方案

状态：已确认设计；实施进度见 [任务台账](development/task-ledger.md)。设计基线日期：2026-10-08。

## 定位和边界

x2Stock 是独立部署的 A 股研究工作台。近期目标是独立应用骨架及用户选择的常规研究模块；长期目标是多 Agent 分析、量化验证及可审计执行。每位使用者在启用相应功能时提供自己的数据源和 AI 凭据；骨架不要求这些凭据，首期单用户，私有数据访问边界预留多用户。

项目使用新目录、独立数据库、数据卷、配置、worker 和全新 Git 历史。旧 3.0 项目仅作为功能、算法、测试和本地历史数据的只读参考；x2Stock 按独立新项目建设。保留兼容能力不意味着继续依赖旧运行目录，也不意味着把旧功能全部照搬。

## 功能整合

市场总览、行情研究、新闻与事件、我的研究、报告与复盘、系统设置构成产品导航。个股行情、资金、相关新闻和用户笔记汇入个股研究上下文，减少孤立页面。旧 Skill 蓝图和数据审计作为系统维护能力；会员、积分、CDK 等商业平台能力不进入本方案。

所有旧业务均登记于[参考目录](modules/catalog.md)，目录不是任务队列。用户选择市场、个股、板块、新闻、个人研究、报告等模块，依赖只补最小前置，取消固定业务顺序；未选模块不建业务表、不部署采集/导入任务。状态为“候选”表示还需要模块讨论，不是开发承诺或迁移授权。接口、字段和算法最终以各模块通过验收的设计为准。

## 推进方法

2026-10-08 用户批准多对话开发与金融专业角色体系：老板确认独立 PM 后释放，PM 按模块三责创建持久专业对话、跟进返工并完成任务内已授权发布。新增开发 Skill 和有行为测试的本地协调机制，未来业务角色按原阶段启用，不建立金融运行器、常驻服务或交易接口。见 [ADR 0005](adr/0005-multi-dialogue-development.md) 与 [模块责任覆盖](development/agent-coverage.md)。

流程为 **用户选模块 → 明确新版功能 → 定义所需数据 → 评估旧数据价值 → 按需另批导入**。默认不迁移；共有功能只是评估条件，用户选定模块、数据集、字段、证券/日期范围及批次后另行批准导入。逐数据集确定粒度、单位、时效、留存和功能验收，选择新采集、有限旧导入、新版重算或不支持。

下一项本体任务见[最小应用骨架](modules/application-skeleton.md)，无需旧项目、数据源凭据或 AI 即可启动；数据库结构升级与旧数据导入分开。数据中心为已启用模块管理配置、任务、来源与质量，随需求增长，不先建设全数据平台或通用搬库工具。

功能状态、数据取得状态、迁移状态分开记录；新采集满足需求即可上线，不等可选迁移。历史缺失、未知 `available_at` 和量化限制如实展示。选择性导入仍遵循稳定快照、血缘/质量/时间检查、幂等、断点及安全回滚，有效新数据优先；这些门槛不强加骨架。旧指标新版重算，不自动复制旧配置、调度、待执行任务或 AI 报告。

本轮路线变更由 [ADR 0006](adr/0006-module-first-new-project.md) 替代旧优先顺序，保留历史决策与审计快照。当前仅交付路线文档；阶段 3 研究、4 量化、5 单独授权执行不变，未实现骨架、业务 Agent 运行器或常驻业务服务。角色覆盖不构成任务授权，历史迁移角色只在评估或选定导入时启用。完成实现后更新台账和交接；核心选择改变时新增 ADR，不静默改写历史决定。阶段路线与交付门槛见 [roadmap](roadmap.md)。

## 仍需后续核验

Tushare 账户实际权限、东方财富/财联社接口稳定性、字段单位和内容使用边界尚未通过新版实测；不能在设计文档中声明已授权或全量可用。概念历史、部分复权因子、旧派生指标的血缘缺口在数据模块单独处置。券商、实盘模型和长期运行安排在相应阶段另行明确。
