# 阶段路线与验收门槛

版本：设计基线 2026-10-08。每个阶段可拆成多次对话和独立模块交付，不设置未经评估的日期承诺。

| 阶段 | 交付 | 进入下一阶段前的验收 |
| --- | --- | --- |
| 0 整体设计 | 文档、功能登记、架构、数据/接口规范、Agent 与协作规则、公开仓库 | 决策一致；链接和配置通过校验；无真实秘密/数据；台账可交接 |
| 1 数据底座 | 独立应用骨架、PG迁移、配置、三类来源、worker、质量中心、只读预览和迁移 | 全新部署可运行；允许来源可验证；重复导入/断点/回滚正确；旧数据未改；失败不清空有效数据 |
| 2 常规业务 | 市场总览→行情研究→新闻事件→我的研究→确定性报告基础 | 每模块有明确字段、显示状态和数据来源；桌面/手机检查；相关规则与归属测试通过 |
| 3 Agent 研究 | 冻结证据、核验/分析/反方/终稿、预算和运行审计 | 数字/引用可核对；时间截止有效；分歧保留；失败可见；费用可控 |
| 4 量化验证 | 策略版本、历史回测、样本外、模拟交易 | 数据口径可重放；无未来信息；披露幸存者偏差；成交约束/费用模型有测试 |
| 5 可审计执行 | 券商接入、风控、订单状态、停止和恢复 | 用户明确启用；订单幂等；异常保护；模拟验收；执行与研究权限分离 |

## 下一轮：数据中心与迁移

从 [模块设计](modules/data-center.md) 开始。先落实数据库/配置和来源能力状态，再只读预览历史数据，最后按数据集执行导入。必须区分：本地导入无需重新下载的数据、需要轻量重建的主表、以及不允许继承的概念成员/未知派生结果。

前端首先做数据中心与配置状态页，首个市场业务页随后建设。旧指标不成为底座的前置依赖。未配置 AI 时数据底座仍可运行；阶段 1 不引入 Agent 编排、向量库、券商和交易任务。

## 每模块完成标准

采用 [交接模板](development/handoff-template.md) 记录目标、输入输出、来源/单位、复用边界、实现状态、验证结果和遗留问题。若任务只交付设计，必须明确标记“未实现”；模块开发不能把候选指标或未知权限写成已经可用。

## 后续单独决策

多人账号、每用户数据源凭据、其他模型/来源、通知渠道、特色指标正式上线、概念历史补齐方法、券商与真实交易启用均由对应模块处理。它们不阻碍阶段 0/1，也不会静默从旧项目带入。
