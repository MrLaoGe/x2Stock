# 阶段路线与验收门槛

版本：设计基线 2026-10-08；当前顺序依据 [ADR 0006](adr/0006-module-first-new-project.md)。每阶段可拆成多轮独立模块交付，不设置未经评估的日期承诺。阶段代表能力演进，阶段 1 不以全数据平台或旧数据迁移完成为退出条件。

| 阶段 | 交付 | 验收边界 |
| --- | --- | --- |
| 0 整体设计 | 文档、参考目录、架构、数据/接口规范、Agent 与协作规则、公开仓库 | 决策一致；链接/配置通过；无真实秘密/数据；台账可交接 |
| 1 最小应用骨架 | Windows EXE+完整项目runtime/根BAT、配置健康、按需Python/SQLite、显式Alembic | 无旧项目/来源凭据/AI可启动；不初始化未选业务表、不采集/导入；结构升级显式、网络和秘密边界正确 |
| 2 按需业务模块 | 用户逐个选择市场、个股、板块、新闻、个人研究、报告等；数据中心随已启用模块增长 | 每模块冻结功能与数据契约，相关行为/归属/界面测试通过；新采集满足需求可上线，迁移可选 |
| 3 Agent 研究 | 冻结证据、核验/分析/反方/终稿、预算和运行审计 | 数字/引用可核对；时间截止有效；分歧保留；失败可见；费用可控 |
| 4 量化验证 | 策略版本、历史回测、样本外、模拟交易 | 数据口径可重放；无未来信息；披露幸存者偏差；成交约束/费用模型有测试 |
| 5 可审计执行 | 券商接入、风控、订单状态、停止和恢复 | 单独用户授权启用；订单幂等；异常保护；模拟验收；执行与研究权限分离 |

## 下一轮：最小应用骨架

从[骨架入口](modules/application-skeleton.md)继续 S1-001；桌面空工作台已由UI-001实现，金融后台/DB仍未实施。桌面部署/存储选择依据[ADR0008](adr/0008-windows-desktop.md)替代旧PG/Compose先决条件。数据库结构升级不等于旧数据导入；本轮不实施二者。骨架不先建设三类来源适配、业务 worker、迁移预览或质量中心；没有旧项目和凭据也能独立启动。

## 骨架之后：用户选模块

流程统一为 **用户选模块 → 明确新版功能 → 定义所需数据 → 评估旧数据价值 → 按需另批导入**。取消市场→行情→新闻的固定队列。[旧功能目录](modules/catalog.md)用于参考，不自动生成任务。仅补当前模块的最小前置，未选模块不建业务表、不部署采集/导入任务。

[数据中心](modules/data-center.md)随已启用模块提供配置、任务和来源/质量管理，不作为前置搬库平台。逐数据集确定字段、证券/日期范围、粒度、单位、时效、留存、功能验收，并选择新采集、有限旧导入、新版重算或不支持。共有功能和迁移评估都不构成执行授权；默认不迁移旧数据。

## 每模块完成标准

按[交接模板](development/handoff-template.md)分别记录功能状态、数据取得状态、迁移状态及证据。新采集满足已选功能即可上线，无需等待可选旧迁移；需要历史而尚无数据的功能明确显示限制，不伪造覆盖或可用时间。

选定导入时另行遵守[迁移规范](data/migration.md)的稳定快照、血缘/质量/时间检查、批次、幂等、断点和安全回滚，保护有效新数据及后续采集。该验收只约束启用的导入范围，不强加骨架或无迁移模块。只有实现与验证完成才标记已实现。

## 后续单独决策

首个业务模块、多人账号、每用户凭据、其他模型/来源、特色指标、概念历史补齐、券商与真实交易启用均另行确认。技术栈、MIT 和长期金融方向保持；当前不开发交易、业务 Agent 运行器或常驻业务服务。
