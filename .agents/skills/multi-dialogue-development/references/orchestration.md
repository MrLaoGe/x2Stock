# 调度与状态契约

这是阶段 0 的开发辅助工具，不是业务 Agent 调度器或常驻服务。

全 worktree 通过 `git rev-parse --git-common-dir` 解析同一个 `.local/orchestration`。文件状态必须原子写入、互斥修改，保存老板/PM/专业对话、角色、授权、依赖、状态、worktree/分支/基线、文件归属、产物、评审与恢复证据。记录不含凭据或私有研究内容。

待创建先登记 dispatch key；pending_creation 的 clientThreadId 不能作为真实 threadId，也不能再次派发。API 返回真实 ID 后单独确认。API 错误或状态不明先查原操作和对话，不自动重建。工具不调用或伪造 create_thread。

任务必须经过依赖接受 → 运行 → 交付 → 独立审查 → 接受。审查退回后保留候选和问题历史，返工产生新候选再复验。取消请求后不自动释放文件所有权；执行者确认停止才终止。进程异常后重新读取状态，不能用内存覆盖磁盘事实。

阶段限制使用角色阶段表：design 模式可在阶段 0 定义未来角色；execution 模式必须满足阶段与额外授权，阶段 5 交易另行授权。冻结的盘前稿保留原快照/截止/摘要，盘后新增版本不能回填；方法、策略、程序、引擎、实验与有效性评估各自归属。

发布锁记录 task_id、pm_thread_id、基线 SHA 和协调版本。占用者即使很久无响应也不能按超时抢占。恢复先提供持有者状态和远端 Git/Actions/标签/Release/通知核对证据；结果歧义保持锁和阻断。释放只能由持有者或有明确恢复证据的协调者进行。

持锁后 fetch origin/main，从远端 VERSION 计算下一 patch；其他 PM 先发布则重新集成并复验，不能保留旧版本预期。推送必须快进；失败恢复同 SHA/版本，不 force push，不修改历史发布材料。最终收据留本地或 Actions，不追加成功提交。
